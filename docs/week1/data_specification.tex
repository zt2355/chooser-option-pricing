\section{Purpose}
This document defines the data required to (a) replicate the BSM-based chooser
option pricing model on JPM, (b) validate it, and (c) supply features for the
ML volatility/pricing models in Weeks 5--6. Every series below maps to either a
\textbf{BSM pricing input} ($S_0$, $\sigma$, $r$, $q$, $T$) or an \textbf{ML
feature} addressing BSM's constant-volatility limitation.

\subsection{Validation benchmark}
Per mentor guidance, CME transaction prices are \textbf{not} required. Week 4
validation benchmarks the BSM analytical chooser price against \textbf{Monte
Carlo simulation} under the same GBM dynamics (convergence check on simulated
payoffs at the choice date). MC prices are generated in-house from calibrated
parameters ($S_0$, $\sigma$, $r$, $q$); no additional external data source is
needed.

\section{Collection Infrastructure}
\begin{itemize}
  \item \textbf{Primary feed:} Yahoo Finance via \texttt{yfinance} (no key, no practical rate limit at daily granularity).
  \item \textbf{Rates feed:} FRED REST API (free key, 120 req/min; 5 series used).
  \item \textbf{Backup feed:} Alpha Vantage (free tier: 25 req/day, latest $\sim$100 sessions only --- full history is premium, hence backup-only role).
  \item API keys stored in \texttt{.env}, excluded from version control.
  \item One-shot pull: \texttt{python -m src.collect\_all}. Automated scheduling via GitHub Actions is a Week 2 deliverable.
\end{itemize}

\section{Known Data Caveats}
\begin{enumerate}
  \item \textbf{FRED missing values}: market holidays are encoded as \texttt{"."} $\to$ parsed to NaN; interpolated in Week 2 cleaning.
  \item \textbf{Calendar alignment}: FRED uses a business-day calendar (1850 rows) vs.\ the NYSE trading calendar (1760 rows); the Week 2 pipeline aligns all series to the NYSE calendar.
  \item \textbf{Adjusted vs.\ unadjusted prices}: both retained; returns/volatility computed on adjusted prices, option moneyness on unadjusted.
  \item \textbf{VIX is index-level (S\&P 500) implied volatility}, used as a market-regime proxy for JPM, not as JPM's own implied vol.
  \item \textbf{VIX dual role}: VIX serves both as a volatility feature and (per mentor guidance) as the sentiment proxy. To limit information overlap, the raw level is used as the implied-volatility expectation while normalized transforms (percentile rank, z-score, momentum) encode the sentiment state; VIX reflects market-wide, not JPM-specific, sentiment.
\end{enumerate}
